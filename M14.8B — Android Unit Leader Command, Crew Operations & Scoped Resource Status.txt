18. RPC ERROR / RECOVERY CONTRACT
======================================================================

For each command and read, classify actual SQL/PostgREST error code or structured response into:

- NOT_AUTHORIZED / current participation lost: hide sensitive affected scope; retain original operation evidence, disable actions.
- SCOPE_CHANGED / ROLE_CHANGED: invalidate affected leader/crew/resource view; reauthenticate/refetch current B1 snapshot, never rely on a previously allowed role.
- STALE_VERSION / STALE_INCIDENT: preserve frozen draft, show current server status and require user to review NEW request if retry with original payload cannot succeed.
- INVALID_UNIT_STATUS / INVALID_TRANSITION: no optimistic state change, explain canonical state/guard.
- PRECONDITION_FAILED / LIVE_CREW / LIVE_RESOURCES / LIVE_TASKS / ACTIVE_UNIT_LEADER: show server failure and human action required; no automatic release cleanup.
- INVALID_TASK_RECIPIENT / INVALID_ACTION_DEFINITION / TASK_LIMIT_REACHED: preserve draft but require explicit re-selection; no substitution.
- OPERATION_REUSED: a reused UUID with different intent is a hard conflict; retain original frozen request.
- HTTP timeout / connection drop after submission: outcome unknown; reconcile same immutable operation/receipt, avoid duplicate.
- HTTP 429 / 5xx / transient network: bounded retry where safe, never infinite.
- expired B1 manifest/cursor: fresh complete snapshot; preserve authorized cached projection when appropriate.
- revoked private messaging/evidence scope: clear only revoked content, not valid unit/task cache.
- incident lease expiry or account logout: hide protected projection; preserve locally protected unsent evidence.
- capacity/oversize: fail explicitly, avoid silent truncation.
- unknown error: safe error display without leaking raw SQL, tokens or personal identifiers.

Do not swallow errors in UI with a generic success boolean. The owner needs to distinguish pending vs confirmed vs attention. A failed privileged write may never be "repaired" by changing an expected version under the same operation UUID.
