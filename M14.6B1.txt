## 1. Main problems to solve

The user has experienced:

1. Moving SIM vehicles appear to jump every 5–8 seconds despite a faster runner schedule.
2. A command to 20 units over a long distance can take an excessive amount of time.
3. Navigation routes appear one by one, sometimes disappear, and sometimes reappear.
4. The manual Refresh button restores routes more reliably than background F4 refresh.
5. A second command to another group sometimes causes the first group's routes to disappear.
6. Some routes appear incomplete, stop before the displayed destination, or fail to start their SIM agents without an obvious explanation.
7. Overlapping vehicles at staging points hide each other and cannot be selected easily.
8. The Navigation section is too large, cannot be collapsed like neighboring sections and crowds out map space.
9. The left/right panel collapse controls appear as blank white buttons.
10. Repeated oversized cards, excessive padding and redundant action buttons make the Command Map harder to use.
11. The map's "Dejanja" floating button overlaps status and confirmation messages.
12. Right-button dragging/panning/rotating the map incorrectly opens the RTS context menu when the button is released.
13. Inspecting a selected unit, its current task, route and destination is not sufficiently immediate.

**Treat these as actual reported defects, not speculative future enhancements.**

The primary goal is a reliable, smooth, map-first RTS experience.

## 3. Fast SIM-position refresh

The user wants vehicle movement to feel responsive.

Currently the backend runner may advance positions more often than the browser fetches them.

Introduce a lightweight, bounded active-SIM-position refresh path targeting approximately **1-second updates while the SIM Command Map is visible and active**.

Requirements:

- Fetch the minimum authorized SIM position/progress data needed for active displayed units.
- Reuse existing incident-scoped authorized reads where efficient.
- Avoid refetching the full incident context, all task history, hydrants or entire route geometry every second.
- Keep the slower F4 operational reconciliation for tasks, sectors, roles, notifications and command state.
- Coordinate fast refresh with the existing F4 provider rather than introducing a competing uncontrolled polling manager.
- Support AbortController, latest-generation fencing, in-flight request coalescing and bounded backoff.
- Pause or reduce refresh when hidden/offline.
- Stop immediately on incident/account/organization change or access revocation.
- Enforce one bounded fast request per scoped refresh cycle, not one request per unit.
- Do not create one Realtime subscription per vehicle.
- Avoid duplicate requests when an existing agent read already supplies a fresh matching snapshot.

Important: A 1-second frontend refresh target is not a guarantee of one new server position per second.

**Do not increase the existing Supabase Cron frequency. The current operational baseline is 5 seconds.**

The UI must accurately disclose the age of the last server-confirmed position.

## 4. Smooth SIM marker movement

Support optional, bounded visual interpolation for presentation between confirmed SIM samples.

Requirements:

- Display an authoritative SIM position as the real known value.
- Cosmetic interpolation must never become a database write or telemetry claim.
- Never extrapolate a marker indefinitely when no new server observation arrives.
- Do not interpolate a real GPS unit using the SIM model.
- Do not move on command issue alone.
- Avoid interpolation across route revisions, teleports, manual repositioning, pause/resume discontinuities or invalidated runs.
- Do not visually overshoot the latest confirmed position.
- When samples are stale, hold at the last confirmed location and indicate staleness.
- Use route-bound progress when available; do not guess movement along a straight line.
- Keep animation frame work bounded and disable animation under reduced-motion preferences.

Choose a clear separation between:

- Confirmed SIM progress.
- Cosmetic display position.
- Original navigation execution plan.

Do not invent human ACK or real GPS data.

- No repeated hydrant/COP layer reconstruction due only to SIM progress.

Do not progressively blank previously rendered routes merely because a new pagination cycle has begun.

Respect existing 25-assignment page and collection-size limits; show incomplete-state warnings honestly.
