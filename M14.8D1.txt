AUTHORITATIVE DOMAIN INVARIANTS
===============================
1. One original operation_id UUID identifies one frozen immutable request, with
   original actor, exact acting organization, incident, assignment/episode,
   action, version, payload, parent relation and any idempotency proof.
   The SAME UUID with a changed request must be rejected; do not rebase and
   mutate a dispatched request while retaining its UUID.
2. An operation may be sent only by its authorized account/organization under
   current capability, visible assignment episode, and permitted active state.
   Reauthorization must happen on reconnect and before network dispatch.
   Cached role or stale lease NEVER grants fresh command authority.
3. Use the existing server command as authoritative; server results and durable
   receipt decide CONFIRMED vs REJECTED. HTTP 200 on unrelated reads, FCM
   delivery, notification open, map selection and locally queued changes are
   not ACK/START/COMPLETE.
4. Identical retry is permitted only if current authorized read allows receipt
   reconciliation and existing immutable request contract supports it.
   If receipt is absent, result remains UNKNOWN; not "definitively failed."
   A definitive first rejection can be corrected ONLY via explicit review and
   a NEW operation UUID. Previously ambiguous attempts must not be erased.
5. Parent/child sequencing: child may be prepared/persisted only if the existing
   queue permits; child dispatch must wait for confirmed parent receipt and the
   authoritative version needed by its exact original request. If that version
   cannot be known before freezing, defer freezing/sending child using existing
   supported mechanism; never silently modify an already dispatched child.
   Do not fabricate successful parent transition or task/version.
6. Cached field incident read lease maximum 24 hours with 2-hour warning,
   conservatively invalidated for authorization loss, uncertain clock/reboot,
   account/org mismatch or confirmed revocation. Registry offline lease remains
   separate (up to 30 days) and must not become a command grant.
7. Privileged server reads execute with auth.uid() and exact org/incident/actor
   guards. Supabase SECURITY DEFINER least privilege and RLS not broadened.
   Unit leader's own-unit authority != IC or organization ADMIN/MANAGER.
8. REAL and SIM/TRAINING are separate. No fake positions, arrival, GPS data,
   resource stock transition in TRAINING, command execution inferred from map.
   No change to existing consent, close or real dispatch rules.
9. Existing audit/incident timeline and original operation receipts immutable.

10. Local unsynced hydrant/picture/inspection/task/evidence data are not deleted

CLIENT-SIDE RECOVERY STATE TRANSITIONS
======================================
Illustrative application-level model (adapt exact current enum names):
 IDLE + human action
 -> freeze and durably persist same-account original request (or refuse)
 -> QUEUED (offline or safe existing worker schedule)
 -> REAUTHORIZING / DEPENDENCY_BLOCKED
 -> SENDING
 -> CONFIRMED if matching original server receipt/canonical projection;
    REJECTED if definitive and first unambiguous server rejection;
    UNKNOWN if network/server/timeout/partial response cannot establish outcome;
    NEEDS_ATTENTION if STALE_VERSION, assignment cancellation/role change,
       server capability/schema mismatch, dependency rejection or revocation.
From UNKNOWN:
 -> read matching receipt under current scope;
 -> if receipt found, reconcile original result and refresh;
 -> if receipt absent, retain UNKNOWN; present exact retry ONLY if canonical
    existing contract supports exact replay and actor is authorized;
 -> if exact retry responds ambiguous, retain identity, evidence and UNKNOWN.
Do not auto-create a corrected version and dispatch it behind user's back.
Retain durable evidence until authoritative resolution and existing retention
policy permit cleanup; never add silent aging/eviction of pending actions.
Queue order is not proof of domain completion.

OPERATIONS / CLASSIFICATION / CONFLICT POLICY
==============================================
Define a source-level matrix for every currently supported offline action and
its actual server RPC. Do not accidentally promote ONLINE_REQUIRED commands
to the offline queue. At minimum consider:
- Assignment ACKNOWLEDGED, STARTED, COMPLETED and existing supported transitions.
- BLOCKED / UNABLE / CANCELLED if already supported by original dispatcher.
- Crew/leader issue, crew join/leave, unit status and resource status remain
  online-only where the current contract says so.
- Existing local photo/inspection and evidence upload continue separately.

Actual error -> user/worker behavior:
 A. HTTP timeout, disconnection, body parse failure, RPC SERVER ambiguous:
    UNKNOWN, original UUID + request retained; receipt reconciliation.
 B. Confirmed matching receipt:
    CONFIRMED and authoritative field refresh; no duplicate domain effect.
 C. DEFINITIVE_NOT_AUTHORIZED / revoked profile/org/assignment:
    hide protected projection; retain local immutable record/evidence locked;
    do not auto retry. Role return requires fresh authorization.
 D. STALE_VERSION or task closed/recipient changed:
    NEEDS_ATTENTION with authoritative diff and explicit human review.
    Preserve old frozen request untouched; new corrected request gets new UUID.
 E. OPERATION_REUSED:
    flag identity mismatch / abnormal replay; never attempt auto-fix by changing
    original request.
 F. DEPENDENCY_PARENT_UNKNOWN:
    child BLOCKED; resolve parent receipt first, no guesswork.
 G. DEPENDENCY_PARENT_REJECTED:
    child BLOCKED_NEEDS_REVIEW; do not auto-send.
 H. ENCRYPTION/LEASE/CLOCK uncertainty:
    protect visible cached incident data and disable dispatch when unauthorized;
    preserve queued local evidence.
 I. Unsupported backend schema/capability:
    show compatibility message; never silently skip canonical server checks.
 J. Partial B1 snapshot, missing gap, cursor drift:
    retain last complete authorized cache; full reset/read as prescribed, NOT
    partial-current success; pending queue untouched.
 K. Duplicate WorkManager delivery / concurrent foreground refresh:
    one in-flight send/receipt resolution for each immutable operation; collapse
    duplicate hints instead of spawning another queue.
 L. Temporary busy response / rate limiting:
    bounded exponential backoff with cap/jitter from existing engine, but never
    rapid polling; visible "retry later" for human.

Be precise: an error may be definitive only when canonical response proves it.
Do not declare NOT_AUTHORIZED from a transient 57014 SQL timeout.
The 57014 error often means statement cancellation or timeout, not evidence
that operation did not commit.
