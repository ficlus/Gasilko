APPROVED FRESHNESS AND RETENTION SEMANTICS
-----------------------------------------
Respect the authoritative M14 incident SPEC section "COP, geometry,
routing and location sharing": a future opt-in source was envisaged as
  - stale after 2 minutes
  - latest position expires after 15 minutes
  - no permanent GPS trail initially
  - observation includes observed time, accuracy and provenance.
These are an existing architectural default, NOT proof that the source
already exists or that sharing consent has been granted.

Proposed C3 view classification (read-only, source-driven):
  - AVAILABLE_CURRENT:
      observation is presently authorized, source=OBSERVED_REAL,
      timestamp trustworthy, 0 <= age < 120 seconds, no expired sharing
      episode and no stale/offline/revoked read condition.
  - AVAILABLE_LAST_KNOWN:
      observation presently authorized, source=OBSERVED_REAL,
      120 <= age < 900 seconds, sharing episode still valid and source
      retention allows the coordinate; never a "LIVE" claim.
  - UNAVAILABLE:
      no genuine/authorized observation, invalid coordinate, invalid
      time/provenance, expired source, age >= 900 seconds, source denied,
      or the source deliberately withholds its coordinates.
  - LOCKED/ACCESS_LOST:
      scope invalid; no coordinates or other protected detail rendered.
  - STALE_SNAPSHOT/OFFLINE:
      user has no current server confirmation. Existing authorized cache
      can be shown ONLY within an unexpired current offline lease AND
      source retention window, styled as last-known/uncertain, never green;
      instantly hide on revocation/lease expiry.

Use server observed_at plus validated server time / bounded clock offset
for online classification where possible; Android elapsedRealtime for
local age growth in a single boot. A changed device wall clock, new boot,
missing trust anchor or future observation must never turn old data
into green. Never reset age because a JSON projection was refetched.
Use explicit source-reported precision/accuracy constraints if present;
do not manufacture accuracy meters. E.g. "Last seen 12 min ago" needs
known observed_at; no timestamp -> "time unknown", not invented age.

Do not preserve/show a coordinate beyond its authorized retention
window even if the user says "last known": after expiry, show grey
"Location unavailable" with non-sensitive last_seen metadata only when
separately permitted. Never extend the retention period without an
explicit SPEC/policy decision and owner approval.

DATA QUALITY & ALGORITHMS
-------------------------
Point validation:
 - shape exactly Point [longitude, latitude], finite numbers,
   -180 <= lon <= 180, -90 <= lat <= 90.
 - Do not mistake [lat, lon] for WGS84 [lon, lat].
 - No NaN, Infinity, null/empty strings, silent zero-zero, or
   invalid "default" coordinates.
 - Do not use `0,0` unless it is a genuinely verified allowed
   observation with provenance; never generate it as a fallback.
 - Observed timestamp must be timezone-aware and sourced from
   authorized observation; never substitute read/refetch time.
 - Reject future observed_at > configured tolerance; any timestamp
   ambiguity -> unavailable.
 - Accuracy is informational; if known invalid/unbounded, do not
   represent it as "precise". Do not infer heading or speed from route.

Classify in a pure presentation function, conceptually:
 classify(observation, trustedNow, scope, sourcePolicy, onlineState):
   if !scopeAuthorized: return LOCKED
   if source != OBSERVED_REAL || !validPoint || !trustedTime:
      return UNAVAILABLE
   if !sourceConsentOrLegalRead || !withinRetention: return UNAVAILABLE
   age := max(0, trustedNow - observed_at)
   if age >= 900s: return UNAVAILABLE
   if readIsOfflineOrStale || age >= 120s:
      return LAST_KNOWN
   return CURRENT
Keep server/source policy authoritative and fail closed. Timestamp
thresholds and semantics follow SPEC defaults unless owner explicitly
approves a policy revision.

Avoid per-frame `Date.now()` as authority: schedule only UI label
updates on an already mounted, active view; use existing refresh state.
No extra network requests just to update an age label.
