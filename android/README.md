# Android foundation

## M2.5 search and filters

The registry now uses domain `HydrantQuery` through `HydrantRepository.list(query,after)`. Search/type/status/active draft and applied state live in the ViewModel. Expand Filters, then explicitly Search or Clear; no requests occur per keystroke. Organization changes reset the whole query; active/inactive/all is available only to MANAGER/ADMIN. Applied filters reconcile successful/conflicting mutations and reload bounded results. The older M2.3 include-inactive checkbox is superseded. [Shared search semantics and M3 replacement contract](../docs/HYDRANT_SEARCH.md) document literals, case, type visibility, pagination and tests. Distance/nearby → M4; inspection due/overdue → M5.

## M2.3 online hydrant registry

ACTIVE accounts enter the registry through the existing Auth gate. `feature/hydrants/domain` defines domain models and the `HydrantRepository` interface; `data/OnlineHydrantRepository` maps JSON transport records and calls existing M2.2 reads/RPCs; `presentation/HydrantViewModel` owns state and operations; Compose consumes domain state only. No database grants, credentials, dependencies, Room entities or sync workers are added.

One authorized organization is selected automatically; multiple memberships can be switched with the visible organization selector. Selection is kept in memory. Switching clears detail/list state, resets the inactive filter and reads only the new organization. Switching is disabled while editing/submitting. Hydrant lists use UUID keyset pages of 100 with Load more. Membership/type/organization metadata is paged too; membership queries explicitly filter the signed-in user rather than loading rosters.

List, detail, add and edit screens provide loading/empty/error/refresh states and Slovenian/German resources. Global initial type names have localized presentation labels; all other configurable types use their stored names. Selection uses explicit type UUIDs and displays global/local scope. Inactive types cannot be newly selected; inaccessible historical type labels display a localized unavailable value. MANAGER/ADMIN can include inactive hydrants, edit master data and deactivate/reactivate. Deactivation requires confirmation. FIREFIGHTER receives create/status only; no role gets type administration or physical deletion UI. Inactive organizations remain readable but mutation controls are disabled.

Mutations use only `create_hydrant`, `change_hydrant_status`, `update_hydrant`, and `set_hydrant_active`; status is excluded from master-edit payloads. Forms validate coordinate pairs/ranges, finite values, usable location, required type and optional positive integer intervals. The server remains authoritative. A form retains its generated UUID across retries. Before retrying creation, the repository checks that exact organization/UUID and acknowledges only a readable row created by the current user. This reconciles an uncertain response without issuing another UUID. It is not a sync queue or a general idempotent-upsert API.

Each existing-row mutation submits the version from its displayed record/edit baseline. On HYDRANT_VERSION_CONFLICT, latest server details load, a localized notice appears and no retry is automatic. An edit draft is retained separately: Review my draft explicitly opens it with the latest baseline, showing the latest server fields above the retained input. The user reviews and saves again. Status/deactivation conflicts return to the latest details for a fresh action. If reload fails, saving stays unavailable until refresh succeeds. No-op/server-returned versions are accepted as returned.

ViewModel state survives rotation. Inputs are memory-only and can be lost on process death; forms explicitly disclose this online limitation. There is no offline write acknowledgement or persistence. Account lock/signout clears registry state and cancels work; stale in-flight results cannot populate another session. Provider exceptions map to bounded error categories and localized messages. Diagnostic logging contains only operation/category, never exception bodies, addresses, notes, tokens or credentials. M3 can replace the repository implementation with Room/sync without exposing Supabase DTOs to Compose.

Validation includes domain/transport/ViewModel JVM tests and Compose tests for firefighter permissions, creation, deactivation confirmation, status conflicts and localized resources. CI runs lintDebug, testDebugUnitTest, assembleDebug and emulator instrumentation plus unchanged database/Web gates. Before deployment, verify against staging on a physical device: two organizations with different roles, permission removal while open, airplane-mode failures and uncertain-create retry, process recreation, large lists, both locales, accessibility/font scaling and deactivation/conflict flows. No GPS, maps, inspections, photos, QR, advanced search or Web registry is included.

Open this directory in Android Studio. JDK 17, SDK 36, build-tools 35.0.0 and Gradle 8.13 are required. The committed wrapper downloads Gradle. Set ANDROID_HOME or untracked local.properties. Minimum device API is 26.

Run `./gradlew lintDebug testDebugUnitTest assembleDebug`. On Windows use `gradlew.bat`. Run `./gradlew connectedDebugAndroidTest` with an API 26+ emulator/device to check a real launch.

M0 has no domain logic and intentionally no JVM unit cases. The unit-test task must execute successfully but NO-SOURCE does not mean behavioral coverage. LaunchTest is a real instrumentation test. Check both Slovenian and German device/app locales.

core and feature directories are explicit future module boundaries, mirrored by packages in :app. Split into Gradle modules as implementations arrive. No repositories, Room tables or sync workers are fabricated in M0; required Room/WorkManager/coroutines runtimes are declared, but no business work runs. Room compiler/KSP waits until entities exist. UI domain reads must later flow through ViewModel → Repository → Room.
