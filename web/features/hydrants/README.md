# Web hydrant registry — M2.4

## M2.5 integration

List reads now use typed `HydrantQuery` and the bounded read-only `search_hydrants` RPC. Search/type/status/active controls submit explicitly and reset UUID pagination. Validated URL state (`org`, `q`, `type`, `status`, `active`, `after`) survives refresh/back/forward and is retained in detail/edit return links. Pages replace the current 50-row result; the older Load more/include-inactive behavior below is superseded. Organization switching navigates with reset filters. See [shared semantics, security, index rationale and performance verification](../../../docs/HYDRANT_SEARCH.md). Distance/nearby → M4; inspection due/overdue → M5.

Routes under `/[locale]/hydrants` (Slovenian `sl`, German `de`): list, `/new`, `/[id]` detail and `/[id]/edit`. An optional catch-all page validates these shapes and UUIDs, validates the existing Auth user/account on every server navigation, and redirects locked accounts through the existing account flow. The account page links ACTIVE users to the registry. No second authentication system is introduced.

`lib/hydrants/domain.ts` owns typed records, drafts, validation, capabilities and mutation field allowlists. `service.ts` encapsulates every hydrant read and the four M2.2 RPCs using the existing browser Supabase client and RLS. `controller.ts` manages loading/content/error/refresh, scoped organization state, mutation guards and conflict review. React consumes typed state through `useSyncExternalStore`; no raw hydrant query is issued by a component. No privileged keys, direct writes, grants, schema changes or new dependencies are needed.

Organization context is explicit. The first usable membership is selected automatically; list users can switch organizations. Each switch clears old hydrants/types and reloads memberships, organization role, available types and the new list. Navigation links carry `?org=<id>`; it is a selection hint, never authority. Unknown or removed membership fails closed. Detail/edit/new pages keep their organization fixed; return to the list to switch. Inactive organizations remain readable but mutation controls are unavailable, matching Android and the RPC contract.

Hydrant lists fetch 50 records per UUID keyset page with Load more. Metadata is paged in batches of 100; own memberships explicitly filter the current Auth user. FIREFIGHTER sees active hydrants and can create/change status. MANAGER and ADMIN can include inactive hydrants, edit master fields and deactivate/reactivate. Native modal confirmation is required for deactivation. There is no physical delete or type administration UI. Type choices are dynamic active global/own definitions; existing inactive references render safely and may be retained. Only seeded global presentation labels are localized by code; selection uses UUIDs.

Creation uses `create_hydrant` with one generated UUID retained across explicit retries. Before retrying, the service checks that exact organization/UUID and acknowledges only a readable record created by the current user; it never updates a colliding record. The returned server-assigned code is displayed, with a link to its detail route. Forms validate coordinate pairs, finite decimal ranges, usable text/location, required type and a positive integer interval. Empty optional fields become null. Create status defaults to UNKNOWN. Master-edit payloads exclude status and all identity/actor/server fields.

Status uses only `change_hydrant_status`; master edits use `update_hydrant`; activation uses `set_hydrant_active`. Each sends the displayed/edit-baseline expected version and accepts the returned record/version. Duplicate calls are blocked synchronously while an operation runs, and successful form submissions cannot be replayed from the same controller. Mutations are never automatically retried.

On `HYDRANT_VERSION_CONFLICT`, the controller reloads latest details and shows a localized notice. Status/activation users make a fresh action from those details. Edit input is retained at its original baseline, with latest server fields shown above it. The user must choose “Review my draft” before the draft gets the latest expected version and Save becomes available. Failed reload keeps submission locked until Refresh succeeds and review is explicit. Ordinary refresh never silently updates an edit baseline. Authorization/unavailable errors clear protected detail/draft state; signout and route disposal invalidate in-flight results.

All messages use the existing flat `messages/sl.json` and `messages/de.json` dictionaries. Forms have associated labels and validation descriptions, disabled fieldsets, progress/alert announcements and error focus. Tables have captions/headers and a keyboard-focusable horizontal scrolling region on narrow viewports. Confirmation uses native modal focus trapping, Escape/cancel and initial cancel focus; failures also appear inside the modal.

M2.5 can extend the service list query and controller filter state without scattering API calls through screens. This milestone adds no advanced search, maps, offline sync, inspections, photos, QR, notifications or import/export. Online drafts are memory-only; leaving/reloading the page discards them, explicitly disclosed in the form.

Verification: `pnpm web:lint`, `pnpm web:typecheck`, `pnpm web:test`, `pnpm web:build`; unchanged Database/Auth/security/concurrency and Android CI. New tests execute domain validation, service RPC/query contracts, controller transitions and server-rendered real TSX using the existing TypeScript compiler, React and Node test runner.

Before deployment, manually verify staging with real sessions: all three roles in two organizations, direct foreign links, membership removal/demotion while a page is open, dynamic/inactive types, uncertain network responses and same-UUID retries, simultaneous edits/status/deactivation from Android and Web. Check both locales at desktop/tablet/320px widths, large datasets, keyboard-only navigation, screen-reader labels/alerts, modal focus restoration and browser back/forward. UI controls improve usability; existing database attack tests remain the security boundary.
