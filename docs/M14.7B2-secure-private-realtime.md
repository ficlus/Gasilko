## SQL contract

New forward-only migration:
supabase/migrations/20261030120000_incident_private_realtime.sql.

private.incident_realtime_read(p_topic text) returns boolean, SECURITY DEFINER,
search_path='', derives actor from auth.uid(). Requires ACTIVE profile and exact
active acting-org membership. Anchored lower-case UUID grammar and length 86 are
checked before casting:
incident:<incident-uuid>:org:<acting-organization-uuid>.

Audience is the union of current canonical Web incident read (including exact
draft-manager or ACTIVE participation/permitted terminal RELEASED participation)
and current pilot field unit/crew visibility. A role name alone never grants it.

granted only to authenticated so the SELECT policy can evaluate it.

- incident_private_receive: authenticated SELECT, extension=broadcast and helper.

  unrelated permissive SELECT policy cannot open incident topics.
- incident_private_no_client_send: restrictive authenticated INSERT namespace deny.
- incident_private_anon_read_guard / incident_private_anon_send_guard: restrictive
  anonymous namespace denies.
No INSERT/presence grant, no public subscription/publication, no RLS enable/disable
statement, no object created inside realtime schema. Other topic namespaces retain

## One optional producer

private.incident_realtime_emit() is a private trigger function (all client grants
revoked). incident_private_hint is a deferred constraint trigger on incident
revision or timeline_sequence advancement. At end of transaction it compares BOTH NEW.revision and NEW.timeline_sequence to the
aggregate's final pair, skipping earlier updates. Under normal initially-deferred
execution and canonical monotonic counters, only the final advancing update matches. Multi-event revisions and revision-only updates share this single producer.
Exact receipt replay without aggregate mutation queues no hint trigger. A later rollback also rolls back messages.

Payload is exactly incident_id, revision, timeline_sequence, with decimal BIGINT
strings and a 512-byte database guard. No task, actor, operation ID, personnel,
text, location, old/new JSON, scope fingerprint or SIM positions.

Up to 50 sorted eligible org topics are derived from active organizations and
canonical participation: ACTIVE or permitted RELEASED terminal history; DRAFT
uses its creator organization. Beyond 50, remaining scopes rely on polling.
Released nonhistorical organizations receive no new hints. Reads still authorize
each actor separately; delivery is not a grant.

realtime.send(payload,'incident_changed',topic,true) inserts optional metadata in
the same transaction; no network/Edge invocation is made. A 100ms lock timeout
bounds optional lock waits. The trigger's exception subtransaction isolates failed
broadcast inserts, including query cancellation, from canonical command effects.
A generic warning has no payload/error details. Missing function/partition or
transport failures may lose hints; polling remains authoritative. No new outbox,
Cron, notification service, dispatch worker or secret.

## Web lifecycle

One private channel per mounted active incident provider; no channel per unit.
The existing browser client/session is used. Managed session account is checked,
Realtime setAuth receives its current access token (never logged/persisted here),
and auth token refresh/sign-in reconnects. Sign-out/account mismatch fails closed.

Subscription success requests an authorized B1 head read; it does not itself set
LIVE. Strict shape/incident/decimal-string/size guards reject invalid hints.
Requested revision and timeline maxima are ephemeral targets, independent of
confirmed head counters and durable B1 cursors. Duplicates/out-of-order messages
do not create notifications or commands.

Hints coalesce on a 750ms timer; an in-flight read retains a trailing dirty flag.
Follow-up uses 1500ms; existing safety polling remains 8 seconds, increasing to
30 on failures. Huge/untrusted future watermarks cannot force an immediate retry
loop. Join errors use exponential reconnect delay with jitter, capped at 30 seconds.
Socket errors request a read; only its authoritative denial calls onAccessLost.
No public fallback after private join denial.

Hidden/offline/unmount/access loss closes the channel and clears reconnect timers.
Scope-local generations discard old callbacks and late auth/session results.
React effect cleanup also unsubscribes the auth listener and cancels reads.
The existing fast SIM lane remains separate; its access-loss state tears down
the main channel too. No hint creates a toast; only authorized timeline/SIM feeds
create the existing bounded notifications.

LIVE requires subscribed transport and a successful read caught up to requested
watermarks. POLLING says updated by regular checks when the read succeeded but
private transport is absent. Refreshing/stale/offline/access-lost use the existing
SI/DE mechanism, with localized POLLING added. Default fallback remains SI.
A socket cannot renew Android authorization or acknowledge local work.

## PR #84 revision-only follow-up

The same incident_private_hint trigger now queues on positive revision OR sequence
advancement. Unchanged counters do not queue it. incident_realtime_emit compares
both saved NEW counters to the final canonical row. Example: (R,S) → (R+1,S) →
(R+2,S): the first deferred event is skipped, the second emits final (R+2,S).
Mixed timeline/revision-only updates behave identically; when both advance in one
update it still queues one trigger event. A later update of unrelated columns
does not add an event. The B1 fallback can append its coarse descriptor for
revision-only writes independently: neither producer changes canonical counters
and the B2 trigger does not depend on fallback execution order.

This relies on canonical monotonic counters and the normal INITIALLY DEFERRED mode.
PostgreSQL allows an operator to force SET CONSTRAINTS IMMEDIATE before subsequent
writes; that can emit multiple transaction-local hints at statement boundaries.
Those inserts remain transactional, are metadata-only and idempotent refresh hints,
and Web coalesces them. We do not claim exactly-once delivery or final-only emission
under forced immediate mode/counter regression by privileged noncanonical SQL.
No extra durable queue, marker table or scheduler is introduced to hide that limit.

Rollback discards inserted broadcasts. Replay without canonical changes emits none.
Optional send failure still loses hints instead of undoing canonical work, with
polling/FCM fallback. Recipient filtering, 50-scope limit, 512 bytes, string BIGINTs,
private RLS, ownership and revoked trigger-function grants are unchanged.
Android remains unsupported for actual WebSockets; no Gradle/schema change.

Related confirmed Web defect: the online handler now clears a stale dirty flag
before queuing a refresh. Previously a hint marked dirty while offline could
suppress scheduling on reconnect, although other triggers could eventually recover.
