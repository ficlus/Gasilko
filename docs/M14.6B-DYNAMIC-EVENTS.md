# M14.6B — Dynamic scenario events

## Inspected contracts before implementation

M14.6A uses strict schema-v1 definitions and immutable published template versions. START captures a private definition snapshot; initialization uses existing COP and SIM provisioning commands, and RUNNING is blocked until initialization is READY. Definition editing requires the existing training operator plus inventory manager capability. Runtime control also requires the existing scenario-controller capability.

The authoritative simulation_scenario_clock advances only through agent_tick. Each runner tick advances at most 50 simulated seconds, bounded by elapsed wall time and scale. Paused scenarios do not advance; resume resets the wall-clock anchor. Eligibility must compare offsets with clock.seconds, never browser or wall time. Ordered ties use the event-plan ordinal.

The current secret-authenticated incident-simulation-runner processes at most five movement ticks, then one H1 automation preparation/road job. Its bearer-secret and service-role boundaries remain unchanged. Scenario events use an additional bounded SQL batch in this runner, not another Cron or browser scheduler. Effects are transactional SQL only, so row locks and atomic history/effect commits replace external-job leases.

Existing simulation_events describe human-authored lifecycle actions. Automatic scenario effects instead have their own append-only execution history and a narrowly typed SIMULATION_ENGINE incident-timeline origin. They never call operational commands as a fabricated user. F4 already consumes incident revision/timeline sequence and localized event codes; H2 map/navigation sources remain independent.

Supported conditions are SIMULATION_TIME, explicit MANUAL, and AFTER_EVENT (an earlier definition event executed). SIM-unit arrival/task-completion conditions are deferred: templates do not have stable pre-existing task-assignment IDs. Access restrictions are advisory annotations, not OSRM closures. Reports, resource requests, communications and phase changes are informational only.

## Definition and runtime contract

- Separate private event plan: `{schema_version:1,events:[...]}`, keyed by template version. The original definition schema remains v1. Missing plans mean an empty timeline. No backfill changes existing running sessions.
- Maximum 40 events / 60,000 plan bytes / 12,000 bytes per event, title 200 characters, description 2,000. Offsets are integer simulated seconds 0–28,800. Only COMMANDER visibility is accepted.
- Trigger has exact keys `mode,offset_seconds,event_id`. Unused fields must be null. AFTER_EVENT must reference an earlier event in the ordered plan, preventing cycles.
- Geographic effect has exact keys `geometry,source_object_id,target_event_id,expected_version`. Point or a single bounded polygon (32 vertices plus closure), validated by the existing COP validator. Use either private inline geometry or a reference to an initial object's frozen geometry. Initial objects are already public; referencing one does not hide that initial object. Use inline geometry for genuinely hidden hazards.
- HAZARD_UPDATE targets an earlier HAZARD_REVEAL in the same session and checks its exact expected annotation version. It cannot edit real COP objects. Repeated updates explicitly chain versions 1, 2, etc.; stale definitions are blocked, never rebased.
- All seven categories are implemented. Non-geographic effects only record information; there is no dispatch, task creation, human ACK, telemetry, lifecycle change, OSRM closure or agent restart.
- SAVE persists definition and plan atomically with the existing template revision and exact-operation receipt. COPY and REVISE copy the event plan; PUBLISH freezes it. START captures a separate immutable session snapshot even for a draft preview.
- Runtime instances retain local event ID, ordinal, unique effect-operation UUID, version, attempts, state, actual result, real timestamp and simulation seconds. Private append-only history records each attempt/cancellation and real instructor actor or SIMULATION_ENGINE origin.
- PLANNED is eligible only by the authoritative clock or dependency. A transaction locks the scenario/clock and event, performs the effect, records history and publishes the incident-timeline entry together. There is no externally visible CLAIMED state or lease to strand: worker crashes roll back the whole transaction.
- EXECUTED and CANCELLED are terminal. BLOCKED/RETRYABLE_FAILURE require an explicitly confirmed retry; at most three attempts total. Cancellation does not count as successful execution and cannot satisfy a dependency. Cancel is allowed while running/paused; execution requires RUNNING and live authority.
- Ambiguous instructor requests retain their UUID and exact expected version in the existing scoped session-storage receipt mechanism. A later retry returns the original receipt without reapplying the effect. A different stale command is rejected.
- Workers process at most five fairly rotated sessions and two due events per session per invocation. Timed events sort by offset, then definition ordinal. Dependent events become eligible after committed prior execution; under load this may take a later invocation. No clock crossing is lost because eligibility uses <= current seconds. Movement ticks remain first; event work has a separate 3.5-second HTTP deadline; H1 preparation follows even if the event call fails.
- RESET does not rearm executed event instances. Replay the template as a new independent scenario; replay tooling is not part of this milestone.

## Authorization and visibility

All five new tables are private, RLS enabled, without browser or service-role table grants. Only the narrow worker RPC is granted to service_role. Instructor commands require existing operator + inventory-management + scenario-controller checks under the shared agent locks; automatic execution rechecks the creator's active operator/membership/manager role and effective command authority, without impersonation.

The ordinary read returns only EXECUTED reports and actually revealed annotation state. It never returns planned IDs, triggers, geometry, definition counts or cancellation/failure details. Instructor reads are separately authorized server-side. A normal command-capable user is not automatically an instructor. Account/org/incident keyed providers abort stale reads and remove data on denied refresh.

The existing incident timeline gets a constrained nullable actor for SIMULATION_ENGINE only; ordinary HUMAN entries still require a real user. A training-event guard ties the engine row to an executed session operation. The timeline reader uses a left profile join for engine events. No fake personnel account is created. F4 consumes the existing incident revision and event stream; SI/DE labels make the SIM origin explicit.

The map adds one independent revealed-only GeoJSON source. Changes do not remount MapLibre, update navigation geometry, clear RTS recipients, discard task drafts or pan the camera. Only the explicit Focus event action moves the camera. Existing unit/task/road interactions retain priority, and ordinary point markers are not swallowed by a hazard polygon.

## Manual acceptance checklist — not executed

- Old schema-v1 templates open/copy/start unchanged; old running scenarios do not gain events.
- Create time events at 0, 30 and 60 seconds, a manual event and an AFTER_EVENT dependency. Save/reopen; copy/revise/publish. Attempt to mutate published plans directly and through RPC: reject.
- Start the same version twice; verify separate instances, annotations, receipts and immutable snapshots. Edit the draft after starting a preview: the existing preview remains unchanged.
- Keyboard/touch add, edit, reorder, delete; create point/polygon geometry; reference an initial object. Invalid geometry, unknown effects, excess counts, future/cyclic dependencies and wrong update targets must be rejected.
- Run at 1x/5x/10x through several offsets. Overlapping worker calls must publish each effect/timeline row once. Pausing prevents both scheduled/manual execution; resume continues on the simulation clock. Finishing prevents new execution.
- Trigger a manual event with explicit confirmation. Repeat/lost-response retry and browser reload must reuse the operation. Reject stale expected versions and cross-scenario IDs. Cancel a waiting event and verify its dependent event remains waiting.
- Reveal a hazard, update expected version 1, then try another update still expecting 1: blocked, original history preserved, no overwrite. Explicit retry stays blocked unless the declared precondition is actually met; max three attempts. A missing target may become available later, then explicit retry can succeed.
- Inspect actual successful/blocked/failed results and paginated history (25 entries/page). No effect/timeline entry on a rolled-back or failed execution. A process/connection failure before commit must leave no partial annotation or stranded claim.
- Revoke creator operator enrollment, membership, manager role or effective command authority while work is pending. Worker must stop effects; instructor controls must be denied/cleared. Re-authorize only through the existing flow, never by event API.
- Ordinary commander and another organization: request instructor=true, private tables, manual command and history directly. Hidden events must not appear in response/SSR/DOM/state or network. Authorized ordinary reads contain only executed reports/annotations.
- Real incidents must never accept events, engine timeline injection or mutations. Human timeline rows must still require a user. No fake ACK, real GPS or task dispatch should be produced.
- With Cron unavailable, events remain pending and worker warning appears. Refreshing/opening the page must not execute work. Restore existing runner and verify bounded catch-up without duplicates.
- Keep H1 moving/preparing routes during a busy event schedule and an event-RPC failure. H2 routes, hydrants and units remain selectable; incoming events preserve camera, RTS multi-selection and open task draft. Focus moves only on explicit click.
- Commander sees localized F4 notification, timeline report and map hazard. Inspect event title/type/revealed time and current annotation version. Access restrictions are clearly advisory.
- Check Slovenian/German, narrow phones, keyboard-only forms, polygon point entry, published read-only view, account/org/incident switches and authorization loss.

## Review and limitations

Source-only review covered SQL delimiters/function signatures/grants/triggers, schema-v1 compatibility, scope/hidden DTOs, transaction/receipt boundaries, TSX nesting/keys, SI/DE entries and worker integration. Tests, builds, lint, typechecks, CI, browser/runtime checks, migrations and deployments were **not executed**. No compilation or database execution success is claimed.

No automated tests were added; the security/concurrency/UI acceptance scenarios above remain a manual verification requirement. No dependencies or protected local customization files changed. Unit-arrival/task-completion triggers, physical simulation, resource consumption, automatic dispatch, route restrictions, replay and the dedicated Scenario Director remain deferred. Scenario annotations intentionally stay separate from real COP editing. Stale update failures require cancellation/new exercise revision rather than silently changing an immutable event definition.
