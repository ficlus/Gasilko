## Actual finite state machines and boundaries

Canonical unit RPC supports ON_SCENE->RETURNING/UNAVAILABLE and
RETURNING->RELEASED/UNAVAILABLE. UNAVAILABLE needs nonempty reason; terminal
transitions require end_crew='CONFIRMED', no active command episode, no live
allocations and no unresolved assignments (M14.5 guard_open_tasks).
An actor currently serving as effective unit leader necessarily has an ACTIVE
command episode, so this surface offers ONLY ON_SCENE->RETURNING. The source
guard, not a UI shortcut, prevents its own release/unavailable action. Existing
commander UI handles command ending/release. No invented dispatch/en-route/
arrival states, observation timestamp, implicit crew ending or task ACK.

No safely reconcilable offline unit observation RPC exists: STATUS is a
versioned state command, not a timestamped observation. Unit/status/crew/resource
commands remain ONLINE REQUIRED. Existing own ACK/start/block/resume/complete/
unable and C/D notes/evidence retain their existing offline queues and dependencies.

Allocation transitions are exactly RESERVED->DEPLOYED/CANCELLED and
DEPLOYED->RETURNED/CONSUMED. Allocation identity, stock owner, unit and quantity
are immutable; no reservation/move/edit stock button. CONSUMED review displays
exact allocation UUID, quantity, localized measure and current/expected versions.
Only canonical SQL locks/decrements stock and appends audit; receipt replay
prevents double consumption. No optimistic local stock/status update.

IMPORTANT source limitation: simulation_resource_guard prohibits INSERT/UPDATE
of incident_resource_allocations for a simulation incident. Resource actions
are disabled in TRAINING/SIM. Do not relax this guard or fake stock just to run
acceptance cases38–45. Owner must arrange a separately authorized controlled
non-SIM inventory acceptance environment, without actual emergency dispatch.
No new SIM instructor/agent controls are introduced.

## Room / immutable review and recovery

Room remains **16**, no migration or generated export change.
Existing INCIDENT_TASK queue/dispatch stores a DRAFT proposal plus immutable
prepared request in ONE transaction. The review captures:
account/org in row, incident/unit, exact leader role id/version, incident version,
unit version, original payload/entity versions, immutable task/catalog/recipient
IDs and snapshot labels/quantity. Review is explicitly NOT SENT / NOT AN ORDER.

Initial confirm refreshes B1 online; requires same current effective leader episode,
same expected incident/unit version, still-eligible own target and current catalog.
No silent substitution of a newer action, member, target or expected version.
Definitive stale draft becomes NEEDS_ATTENTION; human may start an explicit NEW
proposal. No mutation of the original request or deletion of evidence.

SUBMITTING uses existing send() and operation receipt validation. It checks
operation/incident identity, plus task UUID for task issue. Receipt does not
invent allocation/unit/assignment versions. Actual current DTO is reconciled
separately; a confirmed receipt stays confirmed when refresh fails.

SENDING after restart is displayed OUTCOME_UNKNOWN by the existing active-dispatch
seam. Manual retry refreshes current leadership but replays the ORIGINAL request,
including its original expected versions. It does not demand current versions
equal pre-submit versions for an unknown outcome, because the operation itself
may already have advanced them. SQL receipt equality precedes mutation/version
checks. No automatic resend, no fresh UUID after timeout.

The existing worker allowlist is UNCHANGED: own task transitions/messages/evidence
continue; issue/status/crew/resource commands are never background-dispatched.
Attention/unknown manual operations therefore cannot stall its independent drain.
Legacy pilot issue/return records remain manually recoverable within a currently
authorized exact-unit view using their original methods/requests.

Reopening/rotating an issue form first finds its exact account/org/incident/unit/
leader-scoped durable proposal before allocating any replacement command/task/
recipient UUID. Same-scope submitted state is read from Room. Unsent editor text
before Review is ordinary transient UI state; only confirmed review is durable.
New UI selection is keyed by account-scoped model, incident, unit and leader stamp;
old crew search/prepare callbacks cannot populate another scope. No cross-unit
recipient list, no parent role inheritance or auto impersonation.
