## Schema, source boundaries and exact RPCs

public.incident_messages has canonical UUID, incident, sender account/acting org,
audience identity, body, immediate supersedes_id, server sent_at, version=1,
changed_revision and unique operation_id. Composite unit/incident and
predecessor/incident FKs prevent cross-incident references. Trusted writes also
check exact target organization participation and frozen predecessor audience.
A partial unique supersedes_id index permits only one successor. History is never
updated/deleted/truncated. RLS enabled, no ordinary direct table DML/SELECT grants.
Read/write access is exclusively caller-bound security-definer RPCs, search_path=''.

- incident_message_send(p_operation uuid,p_acting_organization_id uuid,
  p_incident_id uuid,p_expected_version bigint,p_payload jsonb) → JSONB.
  Payload: id, body, audience_kind, optional audience_org_id OR
  audience_unit_assignment_id, optional supersedes_id and parent_version.
  p_expected_version follows the existing envelope but is advisory for independent
  message append; it does not authorize/rebase commands. Parent version is strict.
- incident_message_page(p_acting_organization_id uuid,p_incident_id uuid,
  p_before_sent_at timestamptz DEFAULT NULL,p_before_id uuid DEFAULT NULL,
  p_limit integer DEFAULT 30,p_expected_revision bigint DEFAULT NULL,
  p_scope_fingerprint text DEFAULT NULL) → JSONB.
- incident_message_history(p_acting_organization_id uuid,p_incident_id uuid,
  p_message_id uuid) → JSONB, at most 20 immediate predecessors per request.
  next_id permits further authorized traversal.

Private helpers: message_authority(person,org,incident,kind,target_org,unit,write),
message_scope(org,incident), message_dto(row,org). Explicit-person authority is
private/revoked; only M10 invokes it for another person. Public callers never
supply actor identity. Uniform NOT_AUTHORIZED covers inaccessible IDs.
Other safe errors: VALIDATION_FAILED, OPERATION_REUSED, STALE_VERSION,
SCOPE_CHANGED, MESSAGE_SCOPE_LIMIT. Legacy API safe-error mapping is reused.

## Actual access matrix

All ALLOW requires ACTIVE profile, exact active acting-org membership, ACTIVE
incident participation and ACTIVE/STABILIZED incident. Unit target must be a
live deployment in that same incident with ACTIVE participation/organization.

| Actor | INCIDENT read/send | ORGANIZATION read/send | UNIT read/send |
|---|---|---|---|
| Effective IC/deputy | yes/yes | own or active participant org | active units in incident |
| Agency commander | yes/no | own participating org | own organization's units |
| Sector commander | yes/no | own participating org | units in effective assigned sector |
| Unit leader | yes/no | own participating org | exact effective unit |
| Active crew responder | yes/no | own participating org | exact current deployment crew |
| Org admin/manager without command role | yes/no if participating | own participating org | only if independently current crew |
| Nonparticipating/inherited org member | no | no | no |
| PENDING/SUSPENDED/removed member | no | no | no |
| Released/terminal historical participant | no in C | no in C | no in C |

The canonical incident-wide read is participation-based; org admin never gains
incident-wide SEND from organization role. Cross-org organization notes require
effective IC/deputy and active recipient participation. No general organization
records/memberships are acquired. Sector and unit predicates use actual canonical
role/episode IDs plus incident_assignment_effective; stale role labels do not grant
access. Default deny applies elsewhere.

Historical scoped read policy is not sufficiently established for these new
private messages: C conservatively hides message bodies after terminal/released
scope, preserves database/audit/receipt history, and disables send/correction.
This is a documented limitation, not a grant to future organization members.
No PAUSED incident enum is invented. TRAINING uses the same human permissions
and existing incident labels; simulator service activity cannot send as a person.

## Immutable write, replay and corrections

Server normalizes CRLF/CR to LF, trims outer spaces, rejects whitespace-only and
forbidden control characters (normal LF/TAB allowed), and bounds to 4000 Unicode
characters/16000 UTF-8 bytes. No HTML/Markdown execution or cross-scope search.

Commit order: operation advisory lock → involved participant org locks sorted →
actor profile share lock → incident FOR UPDATE → current audience authority →
exact actor/org/normalized envelope receipt replay → locked predecessor/head check
when correcting → increment aggregate revision → immutable row → safe audit
provenance → immutable operation receipt. Notification capture is an AFTER INSERT
trigger in the same transaction. No network is performed while holding locks.

Operation ID and envelope with the server-normalized body are compared exactly on replay.
The normalized request is retained in the private receipt; Android retains its
original frozen client intent independently. A different
request under an existing operation ID is OPERATION_REUSED. New message UUID
collision is rejected. Independent concurrent sends serialize and both remain.
Corrections create a new UUID referencing the immediate predecessor, require its
sender and unchanged audience, and expected parent version=1 plus no successor.
Two competing corrections cannot create two heads. No other-sender override or
retraction feature is invented. Superseded body is available only through current
authorized history. No ordinary hard deletion.

Messages advance aggregate revision only, not incident core version or task
version, and add no shared timeline event/body/target ID. B1's existing deferred
revision-only fallback appends a coarse SCOPE_RESET descriptor atomically.
B2's corrected revision-aware producer emits only incident/revision/sequence.
Timeline sequence remains independent and unchanged by a note. Audit contains
provenance IDs, not the private message body; canonical immutable rows/receipts
retain evidence. Exact replay adds no new revision, audit, row or notification.

## Reads, pagination and scope invalidation

Current heads are ordered by (server sent_at DESC,id DESC), strict keyset cursor,
30 default/50 maximum; never OFFSET. Corrections remove the predecessor from
current heads without changing its historical row. Pages filter every message
through current SQL authority. Targets are similarly filtered, <=100 options;
overflow returns MESSAGE_SCOPE_LIMIT, never a silently widened/truncated picker.
No unrelated profile/roster records are returned.

Message-specific opaque salted fingerprint covers active actor roles/crew,
incident units and participant state. Reads optionally pin expected revision and
scope; mismatch fails before serving a page. B1's field scope is not assumed to
represent all message authority. Android fetches a bounded message head alongside
the same field revision and verifies message scope again before Room commit.
Messages live in an optional message_page JSON member of existing field cache;
data and B1 cursors still commit together. If scope/authority is denied, affected
protected projection is removed immediately, including on history/older reads.
Transient failures retain the prior leased complete cache, marked stale.

Default Android/Web prefetch is 30, retained browsing capped at 100. Every refresh
checks the head, so concurrent sends are not missed by an old history cursor.
Already loaded older rows/cursors are retained while revision and scope are
unchanged; a changed revision resets to the new head to avoid mixed corrections.
A new revision during older-page fetch causes STALE_VERSION and retry/head refresh.
History is fetched online in bounded predecessor batches; only current bounded
heads and local intent are cached for offline viewing. No full-incident complete
message-history cache is claimed. B1's total 3 MiB bound also covers these rows;
larger projections fail without silently committing partial data. Android
history/older failures preserve pending evidence and apply confirmed revocation.

## Android durable drafts and queue

Android discovery remains the pilot's unit/crew-scoped incident list; commanders
without a visible field deployment use Web, not a newly invented Android authority.

Room stays version 16. No new entity/table/column is needed: existing scoped JSON
cache and pending_hydrant_changes/incident_operation_dispatch already represent
the data. Only an existing DAO gains a guarded DRAFT update. No Room export or
migration is introduced solely for messages.

An editor writes an editable DRAFT into the existing queue under original account,
org, incident, operation UUID and message UUID. Autosave is asynchronous; a
keystroke killed before its Room commit can be lost. Committed draft survives
process death. No new background draft service exists. DRAFT payload kind is
incident_message_draft and worker explicitly skips it.

Explicit send validates the current cached target and freezes that SAME queue row
into incident_message_send / LOCAL_PENDING. All further changes/retries use its
original frozen request, operation UUID and message UUID. Existing worker and
remote/identity mutexes send it with other incident operations; no second queue.
Receipt validation additionally matches message_id. Confirmed receipt alone
sets SERVER_CONFIRMED; uncertain transport remains OUTCOME_UNKNOWN, definitive
rejection NEEDS_ATTENTION. Draft history remains retained. Nothing rebases a unit
target, broadens recipients or derives command ACK from reading/notification.

Unsubmitted draft may be edited; submitted request may not. Local pending body is
shown only for a currently cached allowed target; server-confirmed queue entries
do not duplicate the canonical head list. Pending state is distinct from SENT;
SENT never means read/accepted. Corrections share the same draft/send path and
immutable parent/version. Unrelated queues and task dependency/version guards
remain unchanged.

The existing 24-hour incident lease, two-hour warning, earlier org/session expiry
and Keystore proof gate cached message bodies. Existing app-private Room/account
isolation is reused; this milestone does not claim full database encryption.
Account/org checks before/after suspensions, cancellation and identity lock prevent
wrong-account commits/uploads. Known scope loss hides private content while
preserving original pending evidence. Foreground FCM/polling continue; actual
Android private WebSocket remains unavailable without separately approved
realtime-kt, and no Gradle change is made.

## M10 and B2

INCIDENT_MESSAGE category and INCIDENT_MESSAGE_CHANGED event reuse M10 tables,
preferences, devices, leases/retries, delivery worker and generic identifier-only
FCM envelope. Message INSERT transactionally enqueues at most 50 sorted eligible
org events with incident/message/org source key. Duplicate replay does not insert
a message or event. Delivery rechecks dynamic person/org/audience authority and
excludes sender. Unit notifications target unit owner org only; cross-org superior
readers rely on foreground/B2 refresh. This is a safe bounded notification subset,
not an attempt to list every superior recipient in a new system.

Existing notification_recipient is retained under a private legacy name and
wrapped for the new category; other categories delegate to that exact existing
implementation. No broad grants or additional transport/worker. Android adds
the generic category/channel/settings label. Tap opens the already authorized
incident flow, where Messages is reachable; it never ACKs or directly trusts body.
No message ID/body/author/unit/location enters FCM or B2 payload.
M10 enqueue failure rolls back the message transaction; provider failure after
commit leaves the durable message and existing retry telemetry.
