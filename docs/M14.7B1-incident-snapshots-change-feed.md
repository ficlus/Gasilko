## Actual contracts and scope

PostgreSQL remains the canonical incident/task authority. Android reuses
IncidentRepository, incident_field_cache, pending_hydrant_changes,
incident_operation_dispatch, hydrantRemoteAccess, incidentIdentityAccess and the
existing WorkManager. There is no parallel queue, scheduler, aggregate or command
engine. Public command RPCs, immutable operation receipts and M10 delivery are
unchanged.

This first protocol implements the **field participant projection** from PR #82.
It does not widen responders to the commander's full COP, other recipients'
private tasks, resource inventory or SIM instructor data. Incremental typed
subjects are whole FIELD_COLLECTIONS for one incident, not individual canonical
entity versions. Their entity_version is the aggregate revision; nested units,
tasks and assignments retain their own original versions. This deliberately
trades fine-grained transfer size for consistent, bounded bulk reconciliation.

Tables in new forward migration
`supabase/migrations/20261030100000_incident_snapshot_protocol.sql`:
- private.incident_changes: append-only descriptors, PK(incident_id,revision,ordinal).
- private.incident_change_horizons: authoritative retained revision boundary.
- private.incident_sync_limits: private fingerprint salt and serialized cache quota.
- private.incident_snapshot_manifests: actor/org/incident-bound pinned metadata.
- private.incident_snapshot_items: immutable captured collection rows, composite
  owner FK and PK(manifest_id,collection,ordinal). Cascade is temporary cache only.

No historical migration is changed. Clients have no direct table privileges.
Only authenticated callers execute the public read RPCs below; private helpers
are revoked from PUBLIC/anon/authenticated/service_role.

### RPC signatures

- incident_field_directory(p_acting_organization_id uuid)
- incident_snapshot_manifest(p_acting_organization_id uuid,p_incident_id uuid)
- incident_snapshot_page(p_acting_organization_id uuid,p_incident_id uuid,
  p_manifest_id uuid,p_collection text,p_after_ordinal bigint DEFAULT 0,
  p_limit integer DEFAULT 25)
- incident_change_feed(p_acting_organization_id uuid,p_incident_id uuid,
  p_scope_fingerprint text,p_after_revision bigint,p_after_ordinal integer,
  p_limit integer DEFAULT 100)
- incident_field_entities(p_acting_organization_id uuid,p_incident_id uuid,
  p_scope_fingerprint text,p_expected_revision bigint)
- incident_field_timeline(p_acting_organization_id uuid,p_incident_id uuid,
  p_after_sequence bigint DEFAULT 0)
- incident_sync_head(p_acting_organization_id uuid,p_incident_id uuid) — Web only.

All return JSONB. Revision, entity versions, timeline sequence and page ordinals
are decimal strings; bounded small ordinals/counts/schema versions are integers.
Actor is always auth.uid(), never a client actor parameter.

## Consistency and lifetime

Manifest creation holds the existing organization security lock, actor profile
share lock and incident share lock, then calls the explicit field DTO projector.
Canonical incident commands serialize on the same incident row. The captured
core/units/assignments/history records are materialized in the same transaction.
Subsequent pages read only those immutable rows, not mutable canonical tables.
A revision R page therefore remains R when a task changes at R+1.

Each page rechecks ACTIVE profile, exact acting-organization membership, current
unit/crew/effective-role visibility and scope fingerprint. A token is not a grant.
Scope fingerprints use a private salt and reveal neither membership IDs nor
personnel. Changes in visible units, eligible crew/profile/membership state,
effective actor roles or retention horizon force reset. Revoked incident access
raises NOT_AUTHORIZED; stored private pages are not served.

The five-minute expiry is checked server-side on every page. The owner-scoped
manifest lookup, collection counts and contiguous ordinals detect wrong/missing
pages. Android retries an expired/missing manifest once from ordinal zero and
discards every page from the previous attempt. Schema changes, corruption and
oversize results fail safely. No HTTP request keeps a transaction open.

Lock waits are limited to 1500 ms. Canonical commands are not rewritten.
Statement work is bounded by the limits below; this is not a claim of measured
latency. Normal database statement timeouts still apply.

## Producer coverage and privacy

An AFTER INSERT trigger on canonical incident_timeline appends the descriptor in
the same mutation/receipt transaction. Event ordinal supplies deterministic
within-revision order. Multiple events can produce multiple descriptors.
Exact operation replay returns its existing receipt without inserting timeline,
so it does not duplicate descriptors.

Explicit UPSERT allowlist:
- TASK_ISSUED, TASK_CLOSED, TASK_CANCELLED;
- assignment ACKNOWLEDGED, STARTED (including resume), BLOCKED, COMPLETED, UNABLE,
  CANCELLED;
- UNIT_STATUS_CHANGED.

The typed subject is the incident's authorized FIELD_COLLECTIONS. No task text,
recipient UUID, hidden object ID, old values or raw event JSON enters the feed.
A bulk authorized entity read supplies the current core, units/crew, assignments
with task DTOs, and the latest privacy-filtered history window. Replacing a complete
collection removes previously visible rows without inventing physical deletion.

All other timeline classes emit SCOPE_RESET, including core/lifecycle,
participation, command offer/transfer/end/recovery, unit allocation/release/sector,
crew join/leave, resource allocation/transitions, sectors/map objects/hydrant links,
and canonical events emitted by SIM. A deferred incident-row trigger emits a
coarse reset if a revised aggregate has no descriptor after its transaction.
This covers direct aggregate revision writers without rewriting every RPC.
Future unknown timeline classes default to reset, not silent omission.

M14.6 in this source is scenario/SIM infrastructure; there is no separate
operational mobilization/turnout read model to invent here. If such commands are
added, their canonical events initially receive coarse reset. Navigation and
SIM-private agent/hazard/automation streams keep their independent existing
read contracts; their private state is never copied into a REAL field projection.
Full COP/resource/command snapshots and fine-grained entity deltas are not claimed
as delivered: those mutation classes explicitly invalidate the field scope, while
Web rereads its existing authorized modules.

The separate field timeline RPC retains the pilot event-specific allowlists and
assignment visibility. It pages forward by sequence (100 visible events), with
a distinct high watermark. Sequence is never inferred from revision or vice versa.
The existing screen retains its most-recent 100-event window; historical page
transport is available without redesigning the history UI.

## Retention, cursors and resets

Descriptors have a 30-day retention horizon. Bounded opportunistic maintenance
advances the durable floor and removes expired descriptor revisions; it never
edits canonical timeline, receipts or audit. It is demand-driven, not a new Cron.
A missing horizon, cursor behind the floor, future cursor, missing exact cursor,
revision gap or excessive lag produces reset_required with a distinct reason.
No empty-success response hides a missing history segment.

Snapshot/complete collection boundaries use ordinal 2147483647 to mean the entire
revision is captured. Ordinary feed cursors must identify an existing descriptor;
feed keysets are strict lexicographic (revision,ordinal), never OFFSET.
Scope fingerprint includes the horizon so an old projection cannot keep an old
retention context after cleanup. A new complete snapshot establishes a new boundary.

A feed page with supported UPSERTs is followed by one grouped entity RPC pinned
to its advertised current revision. If the incident changes before materialization,
RESET_REQUIRED causes an explicit retry rather than mixed current data. The full
returned field collections supersede all changes through that boundary. A page
with unknown/coarse types or additional pages instead requests a new manifest.
This is bounded collection-level incremental synchronization, not per-entity
patching. An unchanged feed transfers no field content.

## Android atomicity and scope

Room version 16, additive MIGRATION_15_16, adds incident_sync_cursor with
(account,organization,incident) primary key, manifest, revision/ordinal,
independent timelineSequence, fingerprint, schemaVersion and syncedAt.
Existing v15 projection/dispatch and every legacy queue remain intact.

1. Read the authorized bounded incident directory.
2. Immediately remove no-longer-authorized incident projection/cursor, never
   pending operations. Hide narrowed scope before a replacement request.
3. For compatible cached scopes read the feed; otherwise obtain a manifest.
4. Download and validate all pages in memory, including identity, schema,
   revision, sequence, fingerprint, counts, ordinals and byte limits.
5. After a manifest, check changes again; concurrent changes can cause one bounded
   fresh snapshot. No endless refresh loop.
6. Recheck the directory's current scope before commit.
7. Under the existing identity/remote mutexes, atomically save the entire Room
   projection plus all matching cursors. Cursor advancement never precedes data.
8. Renew the existing Keystore lease first, so an interrupted Room commit fails
   closed. No independent lease store is added.
9. If newer revisions were observed during final authorization, report stale and
   let the existing foreground/worker path retry; do not imply caught-up success.

The org-wide committed payload retains the pilot's 3 MiB bound. A failed download
leaves the previous committed projection/cursors, except confirmed scope
revocations which intentionally remove protected projections immediately.
An interrupted staging download has no durable partial pages to recover or clean.
Confirmed receipts, original operation UUIDs, payloads, attention state and parent
dependency/version guards are not touched by replacement. Online-only issue/return
are still never automatically sent by the worker.

Account/organization checks run before and after network suspension and before
the final transaction. In-flight caller cancellation is propagated; the existing
selected-scope gate and identity mutex reject stale account commits. Cache keys
never combine projections from different acting organizations. The existing
global remote mutex prevents overlapping reconciliation, and foreground conflate
retains a trailing hint while a refresh is active.

The maximum 24-hour incident lease, two-hour warning and earliest applicable
organization/session expiry remain unchanged. Online denial clears incident
lease/cache/cursors and preserves pending evidence. Cached registry authorization
does not grant incident commands.

## Web, FCM and diagnostics

IncidentLiveProvider now polls the small incident_sync_head instead of the heavy
incident_context. A changed revision/sequence/authorization fingerprint invokes
the same existing onInvalidate path; commander modules retain their existing
authorized read endpoints. The existing simulation-label adapter still labels
TRAINING, and fast SIM/navigation updates remain unchanged.
Full Web manifest/delta cache adoption is deferred; no Web screen rewrite.

FCM remains identifier-only hints scheduling existing reconciliation. No push
writes Room data directly, runs a command or ACKs anything. Denied notification
presentation still permits foreground refresh. Private Realtime transport is B2;
no public channel or Android dependency is added.

Safe diagnostics include snapshot page/byte counts, feed revision lag, numeric
server creation/feed duration and fixed failure categories. No task contents,
notes, person names, raw tokens or private object identifiers are logged.
Default/SI/DE distinguish unavailable scope, expired snapshot, capacity,
protocol incompatibility, server contention, network failure and generic failure.
The existing stale banner remains separate from confirmed server command receipts.

## Concrete limits and tradeoffs

- 50 visible incidents per directory; overflow is explicit.
- 100 visible units per incident, 100 visible crew per unit; explicit overflow.
- 1000 visible assignments per incident (increased from pilot 100).
- Latest 100 relevant history events; forward history RPC 100/page.
- 3 MiB per field projection and total committed Android org payload.
- 25 rows/page; at most 52 page calls per manifest in Android.
- 3 simultaneous cached manifests per actor/org/incident.
- Global materialized cache: 512 manifests and 64 MiB payload, serialized quota.
- TTL five minutes; remove at most eight expired manifests per creation request.
  Live manifests are never evicted. Under pressure return SNAPSHOT_CAPACITY.
- 100 descriptors/feed page; lag over 10000 revisions or multi-page backlog uses
  a fresh bounded snapshot rather than unbounded client draining.
- Retention cleanup selects 500 expired descriptor rows and deletes their whole
  revisions. A revision may contain multiple events, so deletion may include the
  remainder of the last selected revision. Descriptor storage is time-bounded;
  physical expiration is opportunistic and may lag while no client reads.
- No maximum fake entity count, partial-success truncation or extra scheduler.

The limits prioritize the controlled pilot; very large organizations/incidents
require a future narrower projection/budget change. Snapshot construction may
temporarily allocate more than the final byte budget while building bounded DTOs.
No performance claim is made without human measurements.
