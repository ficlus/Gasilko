  replaceable HYDRANT/INSPECTION cache and is not reused for different audiences.
- `PhotoInputs` / `PhotoCaptureProvider` provide the existing camera scratch

  Incident evidence preserves original bytes instead of using hydrant image
  resize/re-encode. EXIF is NOT claimed to be stripped.
- `SupabaseRegistryTransport.uploadPhoto` proves installed storage-kt 3.6.0
  supports authenticated ByteArray upload with contentType and upsert=false.
  D uses the same SDK operation, bounded to 20 MiB. No Gradle change.
- `IncidentRepository`, Room 16 `incident_field_cache`,
  `pending_hydrant_changes` / `incident_operation_dispatch`,
  existing `HydrantSyncScheduler` and the gateway's existing worker callback
  remain the field read/write/scheduling path.
- Web uses existing Supabase JS 2.116.0, SSR client, loadAccount, acting-org
  arguments, expected-account header and current IncidentLiveProvider.
- `incident-navigation` establishes authenticated Edge REST, auth/v1/user
  verification, isolated existing service-role credential and caller-bound
  authorization before privileged commit. D follows this boundary.
- Existing `hydrant-photos` bucket is limited to 5 MiB and registry authorization.
  D creates ONE isolated PRIVATE `incident-evidence` bucket, not broader photo RLS.
- No secure encrypted incident download cache exists in the inspected source.
  D intentionally uses online-only byte preview/download rather than inventing an
  encryption subsystem or leaving a durable plaintext offline download cache.
  Pending files are durable, app-private, no-backup, not claimed encrypted.

Official capabilities consulted:
[Storage access control](https://supabase.com/docs/guides/storage/security/access-control),

## Canonical persistence

New forward migration, authored only:
`supabase/migrations/20261030160000_incident_private_attachments.sql`.

`public.incident_attachments`:
UUID PK; incident FK; target_kind INCIDENT/TASK/MESSAGE;
target_task_id/target_message_id composite FKs to the SAME incident with RESTRICT;
creator_user_id, acting_organization_id, unique operation_id;
constant storage_bucket, unique derived storage_object_key; sanitized filename;
normalized mime, declared_size and declared_sha256; trusted validated_size,
sha256, verified_at and changed_revision; status, created_at, expires_at,
verification_error. Exact parent-shape CHECK: INCIDENT has neither target FK;
TASK has task FK only; MESSAGE has message FK only.
No inspection ID overload, external URL, binary or signed token is stored.

Path is exactly
`{incident_uuid}/{attachment_uuid}/original.{jpg|webp|pdf}`,
derived on server and checked by SQL. Client labels never determine the path.
Original GPS/filename/org/person are absent from the path.
Declared digest freezes the intended content for replay; it is NOT proof of bytes.
Only the trusted observed digest can populate sha256.

Indexes: unique PK/operation_id/storage_object_key; keyset index
`incident_attachment_page(incident_id,target_kind,coalesce(target_task_id,target_message_id),created_at DESC,id DESC)`;
`incident_attachment_pending(creator_user_id,acting_organization_id,status)`.
No-delete/no-truncate immutable triggers, RLS enabled, no direct table DML/SELECT
for PUBLIC/anon/authenticated/service_role. Only intended SECURITY DEFINER
functions operate on rows, with empty search_path and schema-qualified objects.
The restricted commit never edits READY bytes, target, creator or provenance.

`private.incident_evidence_transfer_limits` is a per-actor/org rolling admission
counter, NOT an event queue, audit log, worker or retained duplicate operation.
PK(actor,organization); five-minute window; maximum 60 authorized access calls.
No direct client/service grants; one atomic ON CONFLICT update, no Cron.

## Exact RPC boundary

Authenticated EXECUTE only (PUBLIC/anon/service_role revoked):

```sql
incident_attachment_prepare(
 p_operation uuid,p_acting_organization_id uuid,p_incident_id uuid,
 p_attachment_id uuid,p_target_kind text,p_target_id uuid,p_metadata jsonb)
incident_attachment_page(
 p_acting_organization_id uuid,p_incident_id uuid,p_target_kind text,
 p_target_id uuid DEFAULT NULL,p_before_created_at timestamptz DEFAULT NULL,
 p_before_id uuid DEFAULT NULL,p_limit integer DEFAULT 30)
incident_attachment_access(
 p_acting_organization_id uuid,p_incident_id uuid,p_attachment_id uuid,
 p_upload boolean DEFAULT false)
```

Prepare metadata is exactly filename/mime/size/sha256. Size is a decimal string.
Prepare is also the uploader status/recovery operation: exact replay returns the
current state and original path, renewing a STAGED insert lease by 30 minutes
after live write authorization. READY replay may recover under current READ
authority (for example after a note correction or completed task); revoked
audiences still cannot recover private data. Operation UUID reuse with different
normalized intent fails OPERATION_REUSED. No separate parallel status model.

Page authorizes the exact target, returns at most limit<=50 metadata items,
authoritative audience and can_add, keyset continuation and opaque current
message scope fingerprint. Only READY is visible to recipients; the original
uploader/org may see its STAGED/REJECTED state. No token/bytes in page.
Clients cap browsing at 100 items, server pages stay navigable beyond that bound
for another permitted client. IDs/timestamps support future report pagination.
No raw audit/event body is returned.

Access distinguishes uploader verification from READY recipient download.
NULL upload mode is rejected. Authorization uses IS NOT TRUE, not nullable
boolean negation as an access grant. Unready bytes never become a normal
recipient download. Each call consumes one bounded transfer admission.

Service-role EXECUTE ONLY (PUBLIC/anon/authenticated revoked):

```sql
incident_attachment_commit(
 p_actor uuid,p_org uuid,p_incident uuid,p_attachment uuid,p_operation uuid,
 p_mime text,p_size bigint,p_sha256 text,p_error text DEFAULT NULL)
```

This is the trusted finalize boundary, not an authenticated caller assertion.
It is reachable in D only from `supabase/functions/incident-evidence/index.ts`
after auth/v1/user and caller-bound access RPC, exact Storage object retrieval,
actual byte inspection and SHA-256. It checks live authority AGAIN under the
existing sorted participant-org/profile/incident locking order. It uses the
existing private.incident_operation_receipts and private.write_audit.
No network request is made while database locks are held.
The service key is an existing Edge environment credential, never Android,
browser, Next payload, response, SQL row or logs. No new secret is requested.

TASK read predicates reuse field_assignment_visible for field recipients and
mirror current can_issue_task/can_execute_task lineage with explicit actor.

forbids new evidence writes to that completed assignment.

including predecessor history. A correction cannot widen old files' audience;
a superseded message cannot accept new uploads. No generic ADMIN or owner bypass.

no simulation auto-command, fake upload acknowledgement or task transition.

## Storage and two-phase state machine

Bucket: private, 20 MiB maximum, MIME allowlist JPEG/WebP/PDF.
Authenticated INSERT only for exact live creator-owned STAGED path within expiry.
Restrictive namespace guards ensure unrelated permissive Storage policies cannot
grant listing, SELECT, UPDATE/upsert/COPY/MOVE/DELETE or anonymous insert/read.
There is deliberately NO authenticated direct object SELECT. The trusted Edge
path is the only normal download path, with current SQL authorization first.
Do not modify Storage system table rows for lifecycle operations.

Local draft/file -> durable LOCAL_PENDING -> server STAGED -> transfer/verifying
-> READY. The stored SQL states are STAGED/READY/REJECTED; transferring/verifying
are transient client activity, not a competing source of canonical state.
These correspond to SPEC conceptual pending/available/attention.
Failures keep OUTCOME_UNKNOWN or NEEDS_ATTENTION and preserve payload/file/UUID.
Rejected bytes remain quarantined. There is no automatic retention cleanup.

Prepare and finalize have distinct stable operation UUIDs. Attachment UUID and
metadata digest/path are frozen. Queue dispatch persists the prepare request
once; retries never rebase/retarget it. Preparation checks the committed parent.
For local message parents the existing dispatch.parent points at that message
operation; a DRAFT is not automatically sent, and upload waits for SERVER_CONFIRMED.
Server rechecks actual parent existence/target. Attention on a parent preserves
the attachment with DEPENDENCY_REJECTED. An independent ACK/START/COMPLETE does
not wait for an attachment and an upload never acknowledges/completes a task.

Restart tries prepare/status and trusted verification BEFORE demanding local
bytes, recovering an uploaded object or lost finalize ACK. Missing/changed local
pending files become attention, not silent deletion. A path conflict never leads
to upsert: trusted verification establishes the existing object's digest.
READY replay cannot bump revision or generate another receipt/audit transition.
Fresh READY atomically advances aggregate revision only; task/core versions and
timeline sequence are unchanged. B1's existing deferred revision-only fallback
creates a coarse safe invalidation, B2 emits identifiers/counters only.
No attachment body/filename/path/hash/token/GPS is put in shared timeline, M10/FCM
or Broadcast. No new notification category, scheduler, worker or realtime channel.

## Trusted content validation

The Edge handler accepts only POST <=4 KiB, verifies JWT via auth/v1/user, and
calls actor-bound SQL. It independently derives and compares canonical
incident/attachment path, then fetches that object with the existing service role.
Received bytes are bounded BEFORE unbounded accumulation to 10/20 MiB, including
unknown/malicious Content-Length. Hash is computed from actual retrieved bytes.
Actual size must equal intent size and trusted hash must equal frozen intended
digest. Content-Type and client digest alone cannot publish READY.

JPEG: SOI/EOI, segment lengths and supported frame dimensions, SOS presence;
WebP: exact RIFF container length, WEBP and image chunk headers/bounds;
PDF: anchored %PDF-1.x/2.x and bounded startxref/EOF structure.
Animated WebP is conservatively rejected. No image/PDF decoder or malware scanner
exists in the inspected Edge dependency set. These are byte signature/structural
checks, NOT a full entropy/PDF object parser, malware scan, antivirus, proof that
a PDF is benign, or EXIF removal. Corrupt image previews fail safely.
PDF is never embedded as browser HTML: download with trusted generated filename,
Content-Disposition attachment, nosniff, sandbox CSP and no-referrer.
Owner must assess malicious/polyglot content and viewer safety before real use.
No unsafe package/import was added to imply stronger validation.

Only service-role commit can set READY, and only after handler byte verification;
SQL additionally checks original row, digest/size/MIME, physical object presence
and live target authority under locks. Ordinary clients cannot call commit,
insert metadata, set verified fields, replace the object or download quarantine.
The trust boundary assumes the existing service-role environment remains secure.

## Android / Room and cache

Room remains version **16**, no migration or generated schema edit required.
Small frozen metadata and operation dependencies reuse the existing queue.
A bounded attachment_pages map (8 target pages, at most 100 rows each) is stored
inside the existing leased account/org incident_field_cache JSON; no bytes/base64.
Pending files use account/org/incident/attachment UUID under noBackupFilesDir.
App allowBackup=false is preserved. Local stage quota includes retained/partial
files; no automatic deletion of queued or acknowledged evidence. No shared gallery
copy and no location metadata in operation payloads.

Existing camera scratch acquisition or system OpenDocument -> bounded copy/magic
precheck/hash -> explicit durable queue. Confirmation shows the selected target;
current server page provides the effective message audience. Pending message
audience comes from the existing draft/immutable message path; no broadening
selector. File/queue confirmation may fail on storage pressure; unregistered
partials are disposable, a finalized unregistered file is retained for manual
inventory, and no server attachment is falsely confirmed. Process death before
Room commit does not promise a registered operation; after commit UUIDs/files
survive restart. No cleanup infers that a pending file is unowned.

Preview is online-only, authenticated, bounded; images remain in memory and are
discarded at closure/revocation. PDF uses an explicit platform document viewer and a non-exported IncidentEvidenceProvider with a random, temporary read-only URI grant. Its bounded in-memory pipe holds no disk bytes; grant is revoked on closure/cancel/scope switch or after 60 seconds. Process death drops all capabilities and bytes. Some external PDF viewers require seekable files and may not support a content pipe: owner must verify intended viewer compatibility; there is no insecure persistent-file fallback.
A hostile external viewer/user can retain a copy. Downloaded bytes are not a
durable encrypted offline cache. There is no encrypted-at-rest claim for pending
app-private files; this follows the existing photo storage approach.

Lease is the existing max24h Keystore-verified incident lease intersected with
organization/session authorization (30-day maximum), boot/elapsed/wall safeguards.
No file/URL extends that lease. Full field loss hides incident plus evidence.
Message-only invalidation atomically strips message_page and MESSAGE attachment
pages only, preserving units/tasks/cursor/lease/queue. Target-specific denial
invalidates that attachment page only. Evidence generation tokens prevent late
page/download commits after narrowing; stale generation pages cannot be restored
by a staged B1 commit. Identity switches cancel UI and recheck current account/
selected org before request and durable commit. Unknown network failure does not
renew the lease, delete files, clear authorized metadata or fake synchronization.

Only one existing ordered incident worker dispatches uploads. Duplicate
WorkManager/manual triggers share the existing mutex; parent dependencies and
receipt history remain. Explicit attention retry uses the SAME operation and file. Pausing future phases/retries uses the existing DRAFT queue state for an already-frozen attachment; resume keeps the request and IDs. An in-flight server finalization may still acknowledge READY; pausing never reverses a receipt. No bytes are deleted.
Photo/registry sync is unchanged. No background privileged UI client.

## Web behavior and limits

One shared IncidentEvidence component is exposed in incident detail, selected
task detail and an explicitly selected message/history entry (no per-message
attachment N+1 list). Effective audience is returned by SQL and shown before the
explicit confirmation checkbox. Default/SI/DE text and visible button labels,
status/alert roles and responsive existing cards are used.
There is no new dependency or pnpm lock modification.

Next POST /api/incidents/evidence checks same-origin, ACTIVE account, live
getUser, X-Gasilko-Account, current session, fixed action/UUIDs and bounded body.
It streams only the authenticated incident-evidence Edge endpoint. No arbitrary
URL proxy, public URL or service-role secret in Next/browser.
Web upload uses existing browserClient Storage insert-only; current account is
checked, identity/generation guards suppress late UI results. Preparation state
and original file are kept in component memory for exact retry; closing the tab
does NOT promise durable offline Web staging. Server STAGED/READY metadata is
recoverable through the authorized page. A lost upload/finalize response does
not create a new UUID on retry.
B1/B2 live.lastSuccess triggers a fresh head read; no independent poll or channel.
Known denial immediately hides page and blob URL. Transient failures do not
pretend READY. Ordinary revalidation clears previews rather than reusing a stale
private capability. PDF downloads only; images use scoped blob URLs revoked on
closure/unmount/identity change, downloads release object URLs shortly afterward.

Policy limits:
- JPEG/WebP 10 MiB, PDF 20 MiB, nonempty; bucket cap20MiB and MIME allowlist.
- 32 live server STAGED reservations and 128 MiB per creator/org.
- Local app-private retained stage data cap128MiB per account/org (conservative
  maximum-file reservation at capture); no automatic evidence deletion to make room.
- Page default30/max50 + lookahead, UI max100, Android max8 cached target pages.
- 60 authorized access RPC calls/account/org/five-minute window; downloads consume
  two due to final authorization, so <=30 downloads/window if no verifies.
  SQL returns ATTACHMENT_LIMIT, Edge maps429; existing worker retries later.
- Attachment transfers allow at most five consecutive transient failures, tracked durably in existing dispatch.error as EVIDENCE_RETRY_n; then NEEDS_ATTENTION. Explicit retry starts another bounded cycle with unchanged IDs/files/request. Existing WorkManager exponential backoff remains unchanged; no global hydrant retry change.
- One upload/download per open Android evidence screen; serialized worker;
  one transfer per Web panel, bounded existing incident/task/message surfaces.
- Edge90s and Next105s timeouts, one object/invocation; platform deployment request/
  memory/concurrency and global Storage size limits remain owner rollout checks.
- No signed URL issued (lifetime not applicable). Own proxy is private/no-store.
  Upstream CDN/browser/external copies cannot be cryptographically recalled.
  New requests always reauthorize; downloaded/screenshot copies cannot be revoked.

Safe codes include ATTACHMENT_TYPE_UNSUPPORTED, TOO_LARGE, MALFORMED, LIMIT,
NOT_READY, NOT_UPLOADED, REJECTED, OPERATION_REUSED, NOT_AUTHORIZED,
STORAGE_TEMPORARILY_UNAVAILABLE and global EXPIRED. Android distinguishes global
401 (field lock) from target403 (page only) and preserves missing-file evidence.
SQL/Edge/provider internals and bearer credentials are not general errors/logs.
