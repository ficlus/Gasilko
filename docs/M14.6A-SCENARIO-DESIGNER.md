## Workflow

Open **Interventions → SIM · Scenariji vaj / Übungsszenarien** for the selected organization. The entry is available to the existing TRAINING simulation operators who also satisfy the existing organization inventory-manager gate. The backend checks the same permissions on every request.

The library has a bounded 25-item page, title search, category/status filters, built-ins, organization drafts, published versions and archives. Choose one of five portable examples (residential fire, warehouse fire, forest-edge wildfire, multi-vehicle collision, sandbox) or create a blank draft.

Built-ins intentionally have **no real-world coordinates**. Copy one, explicitly choose the area's center, and review the suggested incident/object/unit positions. This avoids treating example coordinates as a real incident location. The built-in master stays immutable. The browser does not request GPS.

The separate editor uses the existing MapLibre canvas/style configuration. It has configuration, map and selected-object panels; the side panels collapse on narrow screens. Select center, incident, object or SIM unit from the controls/map. Place points by click/tap, drag the selected point, or apply typed coordinates. HAZARD/PERIMETER polygons are drawn with explicit vertices (including typed coordinate entry), undo and finish. Existing polygon vertices can be edited numerically. Changing map zoom or panels does not recreate the map or change the draft.

Preview mode is read-only. Save is explicit. Publish requires complete, valid placement and freezes that version. Further changes require a new draft revision. Archive preserves all prior versions and sessions. Saved valid drafts also offer an explicitly labelled **test exercise from draft**, retaining their exact snapshot.

## Definition model and limits

- `simulation_scenario_templates`: stable template identity, organization (null only for migration-seeded built-ins), optimistic revision, archive flag and creator/timestamps.
- `simulation_scenario_template_versions`: numbered versions with schema version 1, DRAFT/PUBLISHED state and JSON definition. One editable draft per template; published versions cannot be updated or deleted.
- `private.simulation_template_instances`: exact source-version reference and immutable definition snapshot, organization/creator, initialization status, local-definition-ID → actual object/unit ID mappings.
- `private.simulation_template_receipts`: append-only, exact-request mutation results. Existing incident receipts require a non-null incident and cannot safely represent definition-only changes.

Schema v1 includes metadata (title, category, description, difficulty, objectives, duration, initial situation), world center/location/radius, initial objects, virtual units, public/private briefings, and simulation defaults. There is no executable future-event field.

Server validation rejects unknown keys, real vehicle/organization identity fields and unsupported geometry/profiles. Bounds: 48,000 definition bytes; 40 objects; 30 virtual fixtures; radius 10–5,000 m; duration 5–480 minutes; 20 objectives of up to 500 characters; title/labels 200; description 2,000; initial situation/briefings 4,000 each. Points are finite WGS84 coordinates. Designer polygons have one ring with at most 32 distinct vertices plus closure; lines have at most 32 vertices. The established COP validator additionally checks topology. Stable local IDs are unique across units/objects and cannot use reserved editor IDs.

Virtual composition deliberately uses the existing PROVISION fixture category OTHER, no vehicle identity and no fabricated capabilities/crew. Rufnames/callsigns remain the existing `SIM-<scenario-prefix>-<ordinal>`. Heading is applied as a simulated position, never GPS. Reset retains existing semantics: original spawn coordinates, heading/speed zero.

Clock scale and response profile are stored, displayed **recommendations for the existing confirmed simulation controls**, not silently applied H1 settings. Automatic execution is constrained to false in the definition. Applying clock/profile and enabling automation remain explicit existing instructor actions. No initial sector/deployment association beyond the existing protected deployment is invented.

## RPC boundary and authorization

Existing same-origin `/api/incidents` gains five allowlisted RPCs:

- `simulation_template_list`
- `simulation_template_read`
- `simulation_template_command`: CREATE / COPY / REVISE / SAVE / PUBLISH / ARCHIVE / START
- `simulation_template_initialization`: sanitized instance setup projection
- `simulation_template_initialize`: confirmed bootstrap

All definition reads/writes require the protected TRAINING environment, active account/organization, explicit simulation-operator enrollment and existing inventory-manager authorization. Built-ins are read/copy-only. No browser/direct authenticated writes or table reads are granted; RLS is enabled. There is no broad service-role template endpoint.

Mutations lock organization/profile/operator state, enforce expected revisions and operation UUID exact-payload receipts, then write existing audit records. Instructor definitions are stored only in protected versions/receipts/provenance; public audit records contain references rather than full private briefings. Public instance summary receives only initial situation and commander briefing. Ordinary command readers never receive instructor objectives, briefing or full definition. The sanitized setup projection exposes clock/profile recommendations only to eligible editors in the source organization.

## Safe instance creation and initialization

1. Review saved definition, selected organization, incident type, location, objects and fixture count. Explicitly confirm.
2. START delegates to existing `simulation_create_scenario` / `incident_create_draft`. Incident and scenario stay DRAFT; provenance and receipt commit atomically. Template definitions do not become live incidents while editing.
3. The immutable snapshot is marked **WAITING_COMMAND**. Follow existing commander nomination/acceptance and incident activation. Being an author grants no command authority.
4. The original scenario controller, still an authorized operator/manager with the required live deployment/COP capabilities, explicitly confirms **Prepare objects and SIM units**.
5. A single transaction locks incident/scenario/setup state and checks reviewed incident/scenario versions. It calls existing `simulation_command(PROVISION)`, `simulation_command(SET_POSITION)` and `incident_put_map_object`, chaining their authoritative versions. No direct child inserts or role bypass.
6. The only adapted existing helper, `private.simulation_initial_position`, uses immutable template spawn positions for those fixture ordinals. Legacy scenarios and subsequent extra fixtures retain the original generator. Original spawn/reset positions remain protected.
7. The transaction records local-ID mappings and marks **READY**. Failure rolls back all children and returns to WAITING_COMMAND; no partially committed initialization. A lost response retries the same receipt and cannot duplicate objects/units.
8. Review in the ordinary workspace, apply desired existing clock/profile controls explicitly, then explicitly start the scenario. A database guard prevents RUNNING before READY and prevents manual fixture provisioning/attachment from taking template ordinals while waiting.

H1 runner, navigation service, five-second Cron, task/command authority, F2 commands, F4 updates, G hierarchy, H groups and H2 shared route projection are unchanged. No movement, task, autonomous ACK or scheduled event is created by editing, publishing or initialization.

The browser retains an ambiguous mutation's exact request/UUID in account+organization+surface-scoped session storage and disables competing mutations. Retry is explicit after current authorization is rechecked. Successful acknowledgements and known rejections clear it. Session-storage-unavailable browsers retain retries only while the component remains open; do not discard an ambiguous operation. Unsaved edits have visible warnings, link-leave confirmation and unload protection; they are not server drafts until Save.
