## Implemented flow

F4 now publishes a successful authorized context generation before ancillary notification reads. Its second, registered fast lane is active only while the SIM Command Map is mounted/visible. It performs one bounded sample RPC (100 positions/runs maximum), with aborts, scope fencing, coalescing, visibility/offline suspension and 1–15 second error backoff. Approximately one second is a refresh target, not a new server observation guarantee. Existing agent reads contain no complete position snapshot to reuse; unchanged sample arrays are reused in memory.

H2 retains the last complete authorized collection during requests, partial results and transient errors. A dirty generation runs after the in-flight sequence instead of disappearing. A metadata/membership fingerprint is checked across pages and again at completion. No partial absence removes a route. A changed fast run membership also requests coalesced reconciliation. Completed/cancelled/superseded/invalidated/visibility-changed route removals are distinguished on a complete replacement. Access revocation clears scoped data. Limits stay 25 assignments/page, 1,000 assignments and 250,000 geometry points; an over-limit result is explicitly incomplete and never replaces a previous complete one.

Immutable geometry uses route/session/revision identity; clipping stays ordered spherical arc length. Unit/assignment/session/route identity is independent of RTS selection and other groups' commands. No provider calls for display, source recreation, map remount or automatic camera movement. COP/hydrant source inputs do not change merely because a position sample arrived.

Optional cosmetic marker smoothing lasts at most 750 ms between two already confirmed samples on the same immutable route. It never advances beyond the newest confirmed progress. Reduced motion, stale data, scenario changes, run/state changes and control/event epochs suppress interpolation. Route geometry and selected-unit facts use confirmed progress, never the cosmetic position. Signal loss holds the previous confirmed path instead of disclosing internal simulated travel as current telemetry. Position timestamp is always available; offline/stale mode does not display a frozen age as a current age.

Overlap badges group only point symbols within 22 screen pixels at current zoom. Counts and selected indicators support mixed units/hydrants/tactical points. Passive hover never selects. The persistent chooser uses existing RTS pick/selectMany/clear and workspace detail APIs; Ctrl/Shift toggles and the existing 100-recipient limit remain. Nonunits are inspection targets only. Original coordinates/features remain available for box/lasso. Explicit radial fan-out is visual only, shows at most 16 symbols with leader lines, and leaves the full chooser list available. Area/sector interactions retain their existing map behavior.

Right-drag tracks cumulative pointer movement, retains suppression for the corresponding post-release contextmenu, and resets on the next right-pointer gesture. Touch movement/multi-touch cancels long press. Navigation is initially collapsed; compact rows select the unit without changing authority. SI/DE panel controls have visible labels. Portal hosts inside the existing map wrapper provide separate fixed action and bounded scrollable status zones without resizing MapLibre when notices appear.

Exact destination, reachable road endpoint, current confirmed SIM position, original origin, task/job/run state, queue creation timestamp, and existing correction controls are separate. No teleport, road-access relaxation, alternate provider or automatic mutation was introduced.

## Diagnostics and performance limits

Development-only client diagnostics aggregate numbers once per ten seconds of activity: task request/acknowledgement duration, scoped position fetch and sample age, route collection duration/count, geometry preparation, source submission and next animation-frame delay. They contain no identifiers, coordinates, credentials or payloads. Frame delay is a scheduling observation, not a GPU benchmark.

The authenticated runner response adds movement, event, claim, provider, combined commit/start and total durations, plus existing outcome counts. Queue creation time is exposed through the authorized projection for queue-age diagnosis; it is not claimed as an exact measured provider wait. Position age combines publication cadence and transport latency. No performance measurements were collected in this task.

One route job per invocation remains a real throughput bound: 20 jobs need at least 20 successful claims. HTTP planning does not hold the scenario SQL lock, but additional workers could still compete with ticks/events or exceed provider limits. Follow-up: measure claim wait, provider duration, stale leases and database load with the existing five-second schedule; only then evaluate a bounded two-job preparation batch. No shared route reuse or worker redesign is hidden in B1.
